# PolyTrack AI 自动驾驶(Chrome 扩展)

在**正版 PolyTrack 0.6.3 页面**里加一个面板。点 **▶ 一键自动驾驶**,它按这个顺序规划(谁先成谁用),再回到起点、按方案自动开完:

1. **已有现成方案(内置 / 本机导入 / 浏览器缓存),而且不慢于榜单第 1 名 → 直接开,什么都不算。**
2. 否则取**榜单第 1 名的回放**(只读),先过游戏自带 Verify,再在页面里**微调**(默认 2 分钟),结果存进本赛道缓存——**下次点就是第 1 步,直接开,不再规划**。
3. 榜单读不到 / 没有第 1 名 / 回放校验不过 → 从零求解(见下),同样存缓存。

> 仅个人学习研究。**只支持** `https://app-polytrack.kodub.com/0.6.3/`(补丁依赖这个版本压缩后的代码,版本不对会直接报"游戏版本和补丁不匹配",不会悄悄出错)。

## 安装(Chrome ≥ 111)

1. 地址栏打开 `chrome://extensions`,右上角打开「开发者模式」。
2. 点「加载已解压的扩展程序」,选本目录(`extension/`,里面有 `manifest.json` 和 `autopilot.js`)。
3. 打开 <https://app-polytrack.kodub.com/0.6.3/>,选好赛道,等看到起点画面。页面右上角会出现 PolyTrack AI 面板。

没装扩展、想用油猴(Tampermonkey)也行:新建脚本,把 `autopilot.js` 整个粘进去(文件头已带 `@match` / `@run-at document-start`)。两种装法行为一致:扩展不接管游戏的任何网络请求(它自己只发两种只读 GET,见下面「它做了什么」)。

## 面板

| 控件 | 作用 |
|---|---|
| ▶ 一键自动驾驶 | 按上面的顺序规划后,按 `T` 回到起点自动开。微调 / 求解时按钮变成「取消求解」(取消微调不丢东西:榜单回放通过 Verify 的那一刻就已经存进缓存),开的时候变成「停止(交还给我)」。等同快捷键 `F8` |
| 目标:最快 / 名次 / 秒数 | 默认「最快」。选「名次」填一个**整数名次**(跑完大约排这个名次),或选「秒数」填一个**整数秒数**(跑完大约是这个时间);填完过半秒左右,面板下面会按榜单(只读)算出结果,例如「第 50 名 ≈ 22.303 s」/「23 s ≈ 第 1,234 名」,并写明会用哪条方案。**怎么达到目标**:本机方案就在目标附近(差 ≤ 15 ms)→ 用自己的方案;本机方案比目标快得多(或本赛道没有方案)→ 自己的方案**调不慢**(见下面"已知限制"),所以改用榜单上那一名的回放(只读取得、过游戏 Verify 才开,**不存缓存**),状态栏和日志里明确写着"不是自己的方案";本机方案比目标慢 → 走原来的「最快」流程尽量提速。榜单读不到就报错,不会悄悄改成「最快」。选择和数字记在浏览器里。 |
| 进度条 | 规划 / 微调 / 求解时按阶段显示**百分比**、阶段条(如 准备 → 规划 → 打磨 → 复核)、已用时间和"预计还需"。规划阶段的百分比 = 车在中线上已走到的最远位置 / 中线总长(只增不减,回退重规划不会让条倒退);打磨、榜单回放微调按时间走;复核是最后几秒。读榜单这类不定长的等待用来回扫的条。自动驾驶时同一根条显示"已开 / 方案总时长"。**预计还需只是粗估**:规划阶段遇到急弯停滞、回退重规划时会变长。 |
| 标题栏 | 可拖动(位置记在浏览器里);右上角 ⌃ 折叠成只剩标题栏(折叠后标题栏仍显示百分比和细进度线),再点展开。折叠状态也记住。点日志框可展开 / 收起更多日志行。 |
| 引导线:开/关 | 自动驾驶时,在车前方画一条贴地的发光赛车线(缎带)。颜色 = 方案那一刻按的键:**绿 = 油门,红 = 刹车,黄 = 滑行**,所以刹车点能提前看到;越远越淡,上面的箭头向前流动。开关记在 `localStorage["ptai:guide"]`,默认开;驾驶途中也能切 |
| 状态点 | 状态文字左边的圆点:灰 = 待命,黄闪 = 求解 / 微调中,绿闪 = 自动驾驶中,绿 = 刚完成,红 = 失败 / 出错,黄 = 已停止 / 已取消 |
| 清除本赛道缓存 | 删掉这条赛道已缓存的方案(下次点会重新规划:再取榜单第 1 名 + 微调) |
| 复制回放串 | 复制游戏格式的回放串(base64url) |
| 按键显示(自动驾驶时出现) | W / A / S / D 键帽:亮 = **物理侧此刻实际收到**这个键(不是 UI 自己猜的),旁边文字写「油门 + 左转」之类;下面是按键时间轴(W、A、S、D 四行,黄线 = 现在,左边 2 s 已按过、右边 1 s 将要按),短促的点按在键帽上可能一闪而过,看时间轴更清楚。有方案用到 `R`(重置)时才显示 R 键帽 |

方案按赛道内容的哈希缓存在浏览器 `localStorage` 里,换赛道自动换方案。

**榜单第 1 名回放 + 微调**(`scripts/lib/tas_core.mjs` 的 `polishPlan`,Node 脚本 `scripts/tas_polish.mjs` 和页面里共用同一份代码):在这份已验证的回放上做帧级局部搜索——每个按键翻转帧各平移几帧、短脉冲整体平移 / 缩放 / 插入,每个候选从窗口起点的快照出发模拟到冲线,**目标就是真实完成帧**,只接受更快的,所以结果不会比榜单回放慢;最后再过一遍游戏自带 Verify(完成帧 true、前 1 帧 false、后 1 帧 false),不过就仍用榜单回放原样。页面里的扫描**从终点往起点走**:候选的代价约等于事件到终点的剩余帧数,后段事件便宜,2 分钟预算能覆盖更多事件。榜单回放往往已经是局部最优,所以**常常只快几帧甚至不快**(实测:官方赛道上长时间微调大多 0~2 帧);它的价值主要是"拿到榜单第 1 名的线路,并保证能复现",不是保证更快。微调预算可改:`localStorage.setItem('ptai:polish', '300')`(秒;0 = 只取榜单回放、不微调)。

从零求解(第 3 步):先用滚动时域规划(圈速更好);规划停滞 2 次还不行(新赛道里的墙 / 环 / 长跳常见),自动改用探索式规划(最多 10 分钟,找到任意一条冲线路线),之后都会打磨 30 s 并用游戏自带 Verify 复核。探索法的圈速比规划器慢,但能解出规划器解不出的赛道(官方 summer3 就是)。

## 快捷键

| 键 | 别名 | 作用 |
|---|---|---|
| `` ` ``(反引号,`Tab` 上方) | `F8` | 在起跑线按下即开始自动驾驶:本赛道有方案就直接出发,没有就先求解。再按一次 = 停止并交还按键 |
| `\`(反斜杠) | `F9` | 显示 / 隐藏面板。面板隐藏后快捷键仍然有效,启动自动驾驶也不会把面板弹出来 |

**Mac 注意**:MacBook 内置键盘上 `F8` / `F9` 默认是媒体键(播放/暂停、快进),要先按住 `fn` 才发得出去,所以主键改成了不需要 `fn` 的反引号和反斜杠,`F8` / `F9` 作为别名同时保留。想让 F 键直接可用:系统设置 → 键盘 → 键盘快捷键… → 功能键 → 打开「将 F1、F2 等键用作标准功能键」。

自动驾驶期间**锁死移动键**:`W` `A` `S` `D`、方向键、`R`(重置)、`T`(回起点)在捕获阶段就被吞掉,游戏侧收不到,所以中途乱按不会影响方案(实测:驾驶中连按 `r`/`w`/`r`/`a`,车不重置、不减速、继续按方案跑)。拿回控制权只有两条路:点面板上的「■ 停止(交还给我)」,或者再按一次启动键。`Esc` 不拦,暂停菜单照常能开。

键位可以改,写在 `localStorage` 里(改完刷新页面;值可以是字符串或数组):

```js
localStorage.setItem('ptai:hotkeys', JSON.stringify({ drive: ['KeyQ', 'F8'], panel: ['KeyE'] }));
```

## 它做了什么(以及不做什么)

* 页面加载最早期(`document_start`,MAIN world)接管游戏的物理 Worker:在**你自己的浏览器内存里**给游戏自己的 Worker 脚本打补丁(虚拟时钟 + 批量评估引擎),用 blob 交给游戏。不写盘、不分发游戏文件。
* 不开自动驾驶时,扩展按真实时间把虚拟时钟推进给 Worker,游戏照常可玩。
* **引导线**:方案是确定性的,开车前在评估引擎里把整圈跑一遍(每 10 帧采一个状态,约 0.3 s),得到车接下来要走的轨迹;再从游戏自己的 three.js(WebGL2)里读出相机的 `projectionMatrix` / `viewMatrix`(包了一层 `uniformMatrix4fv` / `drawElements`,**只读矩阵,不改游戏的绘制**),把轨迹投影到一块单独的叠加画布(`pointer-events:none`)上。叠加层是 2D 投影,没有深度遮挡,所以只做了"坡顶后面的路淡出"的近似;被墙 / 环挡住的部分仍可能透出来。只在自动驾驶且开关打开时才有开销。
* 自动驾驶在**精确的物理帧**注入键盘事件(帧号来自求解结果),所以每次开的结果与求解时逐帧一致;求解结果会用游戏自带的 `Verify` 复核(完成帧为 true、少 1 帧为 false)。
* **网络**:扩展**不包装** `XMLHttpRequest`、`fetch`、`sendBeacon`,也不声明 `declarativeNetRequest` 规则;成绩提交、用户资料同步全部由游戏自己走网络,和没装扩展时一样。扩展**自己**只在你点自动驾驶、且本赛道的现成方案不够快时,发两种**只读 GET**:`https://vps.kodub.com/v6/leaderboard?...&amount=1&onlyVerified=true`(取第 1 名的完成帧)和 `.../v6/recordings?...&ids=<那一条>`(取它的回放),不带令牌、不带 cookie(`credentials: 'omit'`),和游戏自己看榜单时发的是同类请求;请求里只有赛道编号(游戏自己的 `Track.getId()`,赛道内容的 SHA-256)。**从不 POST、不上传任何成绩**(构建测试会检查产物里没有写入类请求)。读不到就退回现成方案 / 从零求解。
  面板底部写着"只读榜单、从不上传成绩;成绩是否上传由游戏结算界面决定"。
* **提交须知**:TAS / 机器人成绩能不能进官方排行榜,官方没有明文规则可查。传之前自己去官方 Discord / itch.io 论坛确认一下,分数一旦提交就是公开的。

## 已知限制(都是实测的)

* 求解质量取决于赛道,而且方差很大(同一条 slalom 不同版本得到过 15.6 / 17.4 / 21.2 s)。官方 Summer 1 现在能跑完整圈:内置方案 26.961 s;自己冷求解约 5~6 分钟,冷跑一次得到 31.5 s(求解中途遇到急弯停滞会自动回退重规划,最多 5 次,仍失败时面板显示「求解失败」)。
* 微调 / 求解时页面会明显变卡(评估线程占满核心),微调默认 2 分钟、从零求解要几分钟;期间别切走标签页。
* 榜单第 1 名回放只对**游戏榜单里有的赛道**可用(官方赛道、有人提交过的自制 / 社区赛道);没人跑过的赛道没有榜单,就直接从零求解。赛道编号靠游戏自己的解析器算,和榜单对不上时(比如旧格式赛道)同样退回从零求解。
* **自己的方案调不慢**:逐帧打磨过的方案处在刀刃上。实测(winter5,18.149 s):整体往后移 25 / 50 / 200 / 500 帧(车在起点静止,悬挂状态和刚出生时差 0.001 就够了)、整体后移再用闸门对齐后半段、在 6 个位置插入刹车 / 转向 / 松油门短脉冲(每处 18 种候选),**几乎没有一个能冲线**(能冲线的都是没改变任何帧的空操作)。所以「目标名次 / 秒数」比本机方案慢时,不是把自己的方案调慢,而是开榜单上那一名的回放;想要"自己跑出来的、慢一点的方案"只能从零求解并在目标处提前停止打磨,这版没做。
* 开始自动驾驶前如果车已经跑过,会发 `T` 键回起点;如果游戏没响应,面板会提示你先手动按 `T`。
* 自动驾驶期间游戏的计时由我们的虚拟时钟推进,和你实际墙钟一致(1 倍速);标签页在后台时游戏本来就会暂停。

## 内置方案

`extension/plans/bundled.json` 里是随扩展发布的"已通过游戏 Verify 的回放串"(只有按键翻转帧,不含任何游戏文件),按赛道指纹索引;面板会显示「内置方案」,一点直接自动驾驶,不用现算。本地缓存和内置方案里取更快的那条。目前有五条,都是我们自己离线搜出来的(不是榜单回放),都过了游戏 Verify:slalom(自定义赛道,15.604 s)、官方 Summer 1(26.961 s)、Summer 3(24.858 s,探索 + 压圈速)、Summer 6(47.655 s,探索法,没压圈速)、Winter 1(19.547 s,规划器)。**不是最优**,也不是榜单领先成绩,只是目前抽到的最好一条;Summer 3 / 6、Winter 1 只在引擎里用游戏 Verify 校验过,Summer 3 在扩展页面里完整驾驶验证过,Summer 6 / Winter 1 还没有在真实页面里驾驶验证。其余官方赛道还没有内置方案(summer4 / 5 / 7、winter2 规划器和探索都没跑通,见 `report/phase0.md` 6.16)。

加一条:先用 `scripts/solve.mjs` 求出结果 JSON,再

```bash
node scripts/bundle_plan.mjs --result out/xxx.json --name "赛道名" [--track 导出串文件]   # 不给 --track 用游戏默认的官方赛道;写入前会再用游戏 Verify 校验
node scripts/build_extension.mjs
```


### 只在本机用的方案(`extension/plans/local.json`)

想在自己机器上用"榜单第 1 名回放打底"之类**不能公开**的方案:放进 `extension/plans/local.json`(`{赛道指纹: {name, finishFrames, toggles, recording, source}}`),这个文件被 `.gitignore`,**不进仓库**;`node scripts/build_extension.mjs` 会把它内联进你本机的 `autopilot.js`,面板显示「本地导入:<source>,已通过游戏 Verify」,与内置方案、浏览器缓存里取更快的那条。`node scripts/build_extension.mjs --public` 产出不含本机方案的公开构建(推送前必须用这个)。方案本身用 `scripts/make_local_plan.mjs --recording-file 回放串.txt --frames N --game-track summer3 --out plan.json` 生成,写入前会用游戏 Verify 校验。

## 版本号与版本记录

版本号只在 [`manifest.json`](manifest.json) 的 `version` 里改一处;`node scripts/build_extension.mjs` 会把它写进油猴脚本头(`@version`)和面板页脚(`v0.5.0 · 构建 MM-DD HH:MM · …`),`chrome://extensions` 的扩展卡片上也显示同一个号——重载扩展(点 ↻)后看这几处就知道 Chrome 加载的是哪一版。

**每到一个阶段性进度就升版本号**(并在下面补一行):新增一个用户能感觉到的功能 / 流程 → 升中间位(0.5.0 → 0.6.0);只是修 bug、换 / 补方案 → 升末位(0.5.0 → 0.5.1)。构建测试会检查 manifest、油猴脚本头、页脚三处一致。

### 本地导入方案(不进内置表)

`localStorage["ptai1:<赛道指纹>"]` 里可以放一份 `{v:1, finishFrames, toggles, recording, verified:true, source:"说明"}`;带 `source` 的方案面板显示为「本地导入:<说明>,已通过游戏 Verify」,比内置方案更快时优先用。用 `node scripts/make_local_plan.mjs --recording-file 回放串.txt --frames N --source "说明" --out plan.json` 生成(会先用游戏 Verify 校验)。这是**只在本机**的缓存,不会进仓库;「清除本赛道缓存」可撤销。
