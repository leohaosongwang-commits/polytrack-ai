# PolyTrack AI 自动驾驶(Chrome 扩展)

在**正版 PolyTrack 0.6.3 页面**里加一个面板。点 **▶ 一键自动驾驶**:
没有这条赛道的方案就先在页面里求解(几分钟),再回到起点、按方案自动开完;有缓存就直接开。

> 仅个人学习研究。**只支持** `https://app-polytrack.kodub.com/0.6.3/`(补丁依赖这个版本压缩后的代码,版本不对会直接报"游戏版本和补丁不匹配",不会悄悄出错)。

## 安装(Chrome ≥ 111)

1. 地址栏打开 `chrome://extensions`,右上角打开「开发者模式」。
2. 点「加载已解压的扩展程序」,选本目录(`extension/`,里面有 `manifest.json` 和 `autopilot.js`)。
3. 打开 <https://app-polytrack.kodub.com/0.6.3/>,选好赛道,等看到起点画面。页面右上角会出现 PolyTrack AI 面板。

没装扩展、想用油猴(Tampermonkey)也行:新建脚本,把 `autopilot.js` 整个粘进去(文件头已带 `@match` / `@run-at document-start`)。两种装法行为一致:扩展不接管任何网络请求。

## 面板

| 控件 | 作用 |
|---|---|
| ▶ 一键自动驾驶 | 有方案 → 按 `T` 回到起点后自动开;没有 → 先求解,再开。求解时按钮变成「取消求解」,开的时候变成「停止(交还给我)」。等同快捷键 `F8` |
| 清除本赛道缓存 | 删掉这条赛道已缓存的方案(下次点会重新求解) |
| 复制回放串 | 复制游戏格式的回放串(base64url) |
| 按键显示(自动驾驶时出现) | W / A / S / D 键帽:亮 = **物理侧此刻实际收到**这个键(不是 UI 自己猜的),旁边文字写「油门 + 左转」之类;下面是按键时间轴(W、A、S、D 四行,黄线 = 现在,左边 2 s 已按过、右边 1 s 将要按),短促的点按在键帽上可能一闪而过,看时间轴更清楚。有方案用到 `R`(重置)时才显示 R 键帽 |

方案按赛道内容的哈希缓存在浏览器 `localStorage` 里,换赛道自动换方案。

求解:先用滚动时域规划(圈速更好);规划停滞 2 次还不行(新赛道里的墙 / 环 / 长跳常见),自动改用探索式规划(最多 10 分钟,找到任意一条冲线路线),之后都会打磨 30 s 并用游戏自带 Verify 复核。探索法的圈速比规划器慢,但能解出规划器解不出的赛道(官方 summer3 就是)。

## 快捷键

| 键 | 别名 | 作用 |
|---|---|---|
| `` ` ``(反引号,`Tab` 上方) | `F8` | 在起跑线按下即开始自动驾驶:本赛道有方案就直接出发,没有就先求解。再按一次 = 停止并交还按键 |
| `\`(反斜杠) | `F9` | 显示 / 隐藏面板。面板隐藏后快捷键仍然有效,启动自动驾驶也不会把面板弹出来 |

**Mac 注意**:MacBook 内置键盘上 `F8` / `F9` 默认是媒体键(播放/暂停、快进),要先按住 `fn` 才发得出去,所以主键改成了不需要 `fn` 的反引号和反斜杠,`F8` / `F9` 作为别名同时保留。想让 F 键直接可用:系统设置 → 键盘 → 键盘快捷键… → 功能键 → 打开「将 F1、F2 等键用作标准功能键」。

自动驾驶期间**锁死移动键**:`W` `A` `S` `D`、方向键、`R`(重置)、`T`(回起点)在捕获阶段就被吞掉,游戏侧收不到,所以中途乱按不会影响方案(实测:驾驶中连按 `r`/`w`/`r`/`a`,车不重置、不减速、继续按方案跑)。拿回控制权只有两条路:点面板上的「■ 停止(交还给我)」,或者再按一次启动键。`Esc` 不拦,暂停菜单照常能开。

键位可以改,写在 `localStorage` 里(改完刷新页面;值可以是字符串或数组):

```js
localStorage.setItem('ptai:hotkeys', JSON.stringify({ drive: ['KeyQ', 'F8'], panel: ['KeyE'] }));
```

## 它做了什么(以及不做什么)

* 页面加载最早期(`document_start`,MAIN world)接管游戏的物理 Worker:在**你自己的浏览器内存里**给游戏自己的 Worker 脚本打补丁(虚拟时钟 + 批量评估引擎),用 blob 交给游戏。不写盘、不分发游戏文件。
* 不开自动驾驶时,扩展按真实时间把虚拟时钟推进给 Worker,游戏照常可玩。
* 自动驾驶在**精确的物理帧**注入键盘事件(帧号来自求解结果),所以每次开的结果与求解时逐帧一致;求解结果会用游戏自带的 `Verify` 复核(完成帧为 true、少 1 帧为 false)。
* **不碰网络**:扩展不包装 `XMLHttpRequest`、`fetch`、`sendBeacon`,也不声明 `declarativeNetRequest` 规则。成绩提交、用户资料同步、排行榜读取全部由游戏自己走网络,和没装扩展时一样。
  面板底部只提示"成绩是否上传由游戏结算界面决定"。
* **提交须知**:TAS / 机器人成绩能不能进官方排行榜,官方没有明文规则可查。传之前自己去官方 Discord / itch.io 论坛确认一下,分数一旦提交就是公开的。

## 已知限制(都是实测的)

* 求解质量取决于赛道,而且方差很大(同一条 slalom 不同版本得到过 15.6 / 17.4 / 21.2 s)。官方 Summer 1 现在能跑完整圈:内置方案 26.961 s;自己冷求解约 5~6 分钟,冷跑一次得到 31.5 s(求解中途遇到急弯停滞会自动回退重规划,最多 5 次,仍失败时面板显示「求解失败」)。
* 求解时页面会明显变卡(评估线程占满核心),几分钟;期间别切走标签页。
* 开始自动驾驶前如果车已经跑过,会发 `T` 键回起点;如果游戏没响应,面板会提示你先手动按 `T`。
* 自动驾驶期间游戏的计时由我们的虚拟时钟推进,和你实际墙钟一致(1 倍速);标签页在后台时游戏本来就会暂停。

## 内置方案

`extension/plans/bundled.json` 里是随扩展发布的"已通过游戏 Verify 的回放串"(只有按键翻转帧,不含任何游戏文件),按赛道指纹索引;面板会显示「内置方案」,一点直接自动驾驶,不用现算。本地缓存和内置方案里取更快的那条。目前有两条:slalom(自定义赛道,15.604 s)和官方 Summer 1(26.961 s)。**不是最优**,只是目前抽到的最好一条;其他官方赛道还没有内置方案。

加一条:先用 `scripts/solve.mjs` 求出结果 JSON,再

```bash
node scripts/bundle_plan.mjs --result out/xxx.json --name "赛道名" [--track 导出串文件]   # 不给 --track 用游戏默认的官方赛道;写入前会再用游戏 Verify 校验
node scripts/build_extension.mjs
```

## 重新构建

```bash
node scripts/build_extension.mjs   # 把 page_shim + solver + extension/src/core.js 拼成 extension/autopilot.js
```

测试(用本机 Chrome 像扩展一样注入,点面板按钮,等结果;测试里对 vps.kodub.com 的所有请求都 abort):

```bash
node scripts/test_extension.mjs --track scripts/data/slalom.txt --plan out/mac_slalom_field.json   # 用缓存方案测自动驾驶
node scripts/test_extension.mjs --track scripts/data/slalom.txt                                    # 页面内求解 + 自动驾驶
```

### 本地导入方案(不进内置表)

`localStorage["ptai1:<赛道指纹>"]` 里可以放一份 `{v:1, finishFrames, toggles, recording, verified:true, source:"说明"}`;带 `source` 的方案面板显示为「本地导入:<说明>,已通过游戏 Verify」,比内置方案更快时优先用。用 `node scripts/make_local_plan.mjs --recording-file 回放串.txt --frames N --source "说明" --out plan.json` 生成(会先用游戏 Verify 校验)。这是**只在本机**的缓存,不会进仓库;「清除本赛道缓存」可撤销。
